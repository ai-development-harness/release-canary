## Известный дефект опубликованного релиза

Автоматический запуск остановился после этих основных проверок на `git diff --cached --check`: `.harness/docs/EXECUTION_STATUS.md:621: new blank line at EOF`. Это пустая строка в самом опубликованном v0.12.0; runtime и проектные файлы она не меняет.

Восстановление сохраняет точное содержимое Harness-owned файлов v0.12.0, включая эту строку. Ручная очистка создала бы CURRENT_RELEASE_DRIFT и заблокировала следующее штатное обновление. Ошибка форматирования и отсутствие ранней проверки исправлены в Harness PR #337 для v0.12.1. Тег v0.12.0 и правила проверки форматирования не изменены; PASS для `git diff --check` не заявляется.

## Решение

Продвижение оформляется отдельным recovery PR с явным описанием известного дефекта. База становится принятой только после успешного независимого Harness Integrity CI, проверки diff и merge этого PR. После принятия требуется повторить qualification v0.12.1 от новой базы v0.12.0.

По запросу maintainer лимит всех трёх заданий Harness Integrity увеличен до 15 минут. `.github/**` относится к shared ownership: эта настройка canary допустима и не меняет 332 точных Harness-owned файла v0.12.0. Набор и строгость проверок сохранены.
